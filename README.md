# マンナカ

N人会議場所最適化エージェント。参加者全員の出発駅から、宣言した公平性ポリシーで
集合場所の候補を並べ、**誰がどれだけ損をしているか**を人の表情で突きつける。

「いつも本社」で終わる場所決めを、根拠を言える比較に置き換える。

設計は [設計書.md](設計書.md)、開発手順は [CONTRIBUTING.md](CONTRIBUTING.md)、
Cloud Run へのデプロイは [DEPLOY.md](DEPLOY.md) を参照。

## 起動

```bash
docker compose up --build
```

| URL | 中身 |
|---|---|
| <http://localhost:8081> | トップページ（機能と使い方） |
| <http://localhost:8081/app> | アプリ本体 |
| <http://localhost:8081/docs> | OpenAPI ドキュメント |

Firestore エミュレータも一緒に立ち上がり、会議と監査ログはそこに保存される。

## 使い方（`/app`）

ログインは無い。開くとすぐ入力フォームが出る。

1. **参加者を入れる** — 名前と出発駅。行は増やせる。モックが知らない駅は理由つきで弾かれる
2. **候補地** — 「早い」「バランスよく」「安い」を切り替えると**選ばれる駅が変わる**
3. **3カラム** — 左に地図（選択中の候補地と、誰がどこから来るか）、中央に候補、
   右に参加者の様子。候補を押すと地図も表情もその場所のものに変わる。
   地図は MapLibre GL JS ＋ CARTO Positron（鍵なし）。タイルを読めないときは
   座標だけの略図に落ちる。
   3カラムに足りない幅（1080px未満）では候補リストだけを出し、候補を押すと
   地図・様子・その候補をひとつのモーダルに重ねて開く
4. **表情** — その候補地での移動時間の重さで顔と姿勢が変わる
   （楽なら万歳、いちばん重い人は赤くうなだれる）。
   その基準での最良には「おすすめ」が付く
5. **記録** — どの基準でどう評価したかの証跡が会議ごとに残る

## 公平性ポリシー

同じ参加者でも、宣言する基準で結論が変わる。どれで選んだかを常に明示・記録する。

| ポリシー | 画面の表示 | 意味 |
|---|---|---|
| `sum` | 早い | みんなの移動時間の合計が最小 |
| `minimax` | バランスよく | いちばん遠い人の負担を軽くする |
| `cost` | 安い | みんなの運賃の合計が最小 |

## ガバナンス（設計書 §8 の実装箇所）

| 方針 | 実装 |
|---|---|
| 個人情報を持たない | 受け取るのは名前と出発駅だけ。住所も連絡先もアカウントも作らない |
| 判断は人が握る | どこに集まるかは決めない。候補と、誰がどれだけ負担するかを出すところまで |
| 公平性の宣言 | `policy` は常に会議に保存され、候補の説明文にも監査ログにも出る |
| 可観測性 | `AuditService` が Firestore と構造化JSONログの両方へ記録。候補の内訳も payload に含む |

## 現状と残り

**実装済み**: 入力フォーム、候補算出と3ポリシー、負担の可視化（地図・表情）、
希望条件からの基準の読み取り、監査ログ、REST API、ADKエージェント定義、
Firestoreリポジトリ、Cloud Run へのデプロイ。

**実APIへの接続**: 駅すぱあとAPI・Gemini とも実キーで疎通を確認済み。
既定はモックのままで、環境変数で切り替える。Gemini が高負荷で `503` を返した
とき、候補算出そのものが `500` で落ちる経路が残っている（LLM は説明文の生成に
しか使っておらず、落ちる必要がない）。

**持たないもの**: ログイン、通知、カレンダー連携、会議室予約、当日の遅延フォロー。
場所を比べるところに絞った結果として落とした。
